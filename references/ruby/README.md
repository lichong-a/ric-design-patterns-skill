# Ruby · 设计模式选择指南

[← Skill 入口](../../SKILL.md) · [验证记录](../../docs/VERIFICATION.md)

**代码目标：Ruby 3.1+ 目标。** 目标版本不是所有发行版/平台的兼容性承诺，实测版本见验证记录。

本语言来自用户参考站的语言目录；本项目示例为独立新编。

## 先看本语言的取舍

- 鸭子类型、block/lambda、Enumerable 与组合通常更惯用；协议契约依赖测试而非大量空接口。
- dup/clone 与 freeze 都需要解释实际深度；字符串也是可变对象，复制数组并不总够。
- 没有原生 final；闭包和订阅可能保活对象；不要把某个实现的线程执行特性当所有 Ruby 的保证。

## 创建型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [工厂方法 · Factory Method](factory-method.md) | 框架已经有创建者扩展点，需要让扩展实现决定具体产品。 | 只有一个稳定构造函数，或一个配置到构造函数的映射已经足够。不要为了一个 new 增加整套继承树。 | 鸭子类型产品只需响应 render；创建者的 protected make 保留继承扩展点。 |
| [抽象工厂 · Abstract Factory](abstract-factory.md) | 需要切换主题、平台、协议家族，且一个家族包含多种必须配套的产品。 | 只有一个产品种类，或者产品之间不需要兼容约束。 | 工厂协议由 button/checkbox 方法约定而非空接口类构成；行为契约需要共享测试，不能以 respond_to? 证明产品族语义相容。 |
| [生成器（建造者） · Builder](builder.md) | 有多步骤、可选字段、跨字段校验，或需要用相同组装过程产出不同表示。 | 少量必填参数可由清晰构造函数、命名参数或不可变记录解决。 | 链式方法返回 self；对选定的字符串、数组和成品逐层复制/冻结。 |
| [原型 · Prototype](prototype.md) | 对象配置昂贵、类型运行时确定，或用户从已有模板派生对象。 | 对象含不可复制资源，或直接构造简单值已足够。 | dup/clone 默认浅复制；initialize_copy 为本对象结构复制数组及其可变字符串。 |
| [单例 · Singleton](singleton.md) | 确有唯一实例约束的进程内只读配置或协调对象，且其边界已被证明。 | 只是为了方便调用；需要按租户、请求、测试隔离，或实际上应该使用依赖注入。 | 使用标准库 Singleton 而非自行手写脆弱初始化。 |

## 结构型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [适配器 · Adapter](adapter.md) | 集成遗留代码、第三方 SDK 或不兼容协议，需要做可追踪的边界转换。 | 新旧接口本已一致；或适配层掩盖了无法保证的语义兼容性。 | 鸭子类型的 meters 协议无需空基类；组合旧对象并转换单位。 |
| [桥接 · Bridge](bridge.md) | 产品确实存在两个独立、持续变化的维度，例如消息形式 × 发送渠道。 | 只有一个变化维度，或所谓第二维只是一个固定实现细节。 | 通道协议取名 send_message，避免与 Ruby Object#send 的反射分派混淆。 |
| [组合 · Composite](composite.md) | 领域天然是树形的整体—部分结构，叶子与容器存在有意义的共同操作。 | 结构本质是含环的图，或共同接口必须塞入大量叶子不支持的操作。 | sum(&:total) 让叶子/组合遵循统一协议；数组快照保护成员列表，但不保证所有节点对象不可变。 |
| [装饰 · Decorator](decorator.md) | 功能要在运行时按需叠加，包装与被包装对象具有可替换的契约。 | 只是一次简单函数变换，或包装后已经改变了原接口语义。 | 显式转发比无边界 method_missing 更清晰；若使用 Delegator/Forwardable，要确认对象身份、额外方法与资源释放是否仍符合接口契约。 |
| [外观（门面） · Facade](facade.md) | 存在真实的多组件子系统，客户端只需要少数稳定用例。 | 一个入口不断承接所有业务职责，逐渐形成上帝对象。 | 构造注入让协调流程易于替换测试；外观未吞异常。 |
| [享元 · Flyweight](flyweight.md) | 内存测量显示重复、可共享的状态占比高，且共享对象可保持不可变。 | 对象数量很少、键空间巨大，或共享可变数据带来的同步成本超过节省。 | equal? 检查共享身份，freeze 同时施加到字体字符串与 Style。 |
| [代理 · Proxy](proxy.md) | 需要延迟加载、访问保护、缓存或远程调用边界，且客户端仍面向相同主体契约。 | 仅为隐藏所有网络成本或失败而宣称远程对象和本地对象完全透明。 | 惰性字段保留 read 协议，同时控制首次创建。 |

## 行为型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [责任链 · Chain of Responsibility](chain-of-responsibility.md) | 处理顺序可配置，并且停止条件、默认结果与传递语义明确。 | 必须执行的步骤不允许跳过，却使用可能无人处理的隐式链。 | lambda/Proc 表达处理动作，显式后继保持责任传递。 |
| [命令 · Command](command.md) | 需要排队、历史记录、延迟执行、撤销，或将请求传给通用调用器。 | 调用没有生命周期、历史或排队需求，一个函数已充分表达意图。 | 符号阶段配合异常校验执行/撤销顺序；命令保存接收者引用，不是复制接收者。 |
| [解释器 · Interpreter](interpreter.md) | 文法小且稳定、表达式可以组成语法树，需要可控的领域规则求值。 | 语言复杂或不可信输入需要完整解析、资源治理；此时应使用成熟解析器/执行引擎。 | Hash#fetch 对缺失变量显式失败；节点遵循 evaluate 协议，不调用 Kernel#eval。 |
| [迭代器 · Iterator](iterator.md) | 需要统一遍历不同集合、惰性读取，或让多个遍历彼此独立。 | 语言已经提供足够的集合协议，却再包装出不兼容的 next/hasNext 框架。 | 实现 each 并混入 Enumerable 即可复用集合操作；无 block 返回独立 Enumerator。 |
| [中介者 · Mediator](mediator.md) | 多个组件有明确的一组协作规则，需要减少组件间相互引用。 | 只有简单广播，没有集中决策；或者中介者膨胀到管理整个系统。 | block/lambda 将控件通知汇聚到 Dialog；各控件不引用彼此。 |
| [备忘录 · Memento](memento.md) | 需要撤销、检查点或恢复，且快照大小与敏感信息可控。 | 状态巨大或包含不可恢复的外部副作用；不能把快照当成分布式事务。 | 文本复制加冻结保护快照，恢复时再复制避免编辑改到历史。 |
| [观察者 · Observer](observer.md) | 一个对象变化需要通知动态集合的订阅者，订阅生命周期可管理。 | 需要持久消息、跨进程投递或恰好一次保证，却只有内存回调列表。 | Hash#values 返回本轮回调数组快照，允许回调自退订；订阅需要 block。 |
| [状态 · State](state.md) | 同一对象有明确状态图，不同状态的行为或转换规则会继续扩展。 | 只有两个简单状态且分支集中，枚举与清晰条件表达已足够。 | 鸭子类型状态实现同一事件协议，状态自身决定下一态；Context 只转发。 |
| [策略 · Strategy](strategy.md) | 存在真实、可互换的算法族，需要独立测试或运行时选择。 | 只有一条稳定算法，或者参数本身已能清楚表达差异。 | lambda 直接表达单操作策略；多方法、资源或可观测状态才更适合策略对象。 |
| [模板方法 · Template Method](template-method.md) | 流程骨架稳定，已有合理继承/trait 扩展点，部分步骤需要定制。 | 子类需要随意改变流程顺序，或组合函数比继承更清晰。 | 稳定 run 调用受保护步骤，Ruby 不原生强制 final，需要测试约束。 |
| [访问者 · Visitor](visitor.md) | 节点类型集合相对稳定，新增操作比新增节点类型更频繁。 | 节点类型经常变化，或简单模式匹配已经更清楚。 | 通过显式 accept 与不同 visit 方法实现双分派，不用反射拼方法名绕过接口。 |

## 横向选择：先定位变化轴

### 对象如何产生

[工厂方法](factory-method.md) / [抽象工厂](abstract-factory.md) / [生成器（建造者）](builder.md)

已有创建者扩展点 → 工厂方法；必须配套的一族产品 → 抽象工厂；分步构建且须校验完整性 → 生成器。

**先比较更简单方案：** 只有一个稳定构造过程时，用构造函数、具名参数或简单构造函数映射即可。

### 包装一个对象

[适配器](adapter.md) / [装饰](decorator.md) / [代理](proxy.md) / [外观（门面）](facade.md)

接口不兼容 → 适配器；同契约叠加责任 → 装饰；控制访问/按需创建 → 代理；简化多个子系统 → 外观。

**先比较更简单方案：** 不能只看包装类外形判定；先说明客户端契约是否改变。

### 组织对象结构

[桥接](bridge.md) / [组合](composite.md) / [享元](flyweight.md)

两个独立变化轴 → 桥接；整体与部分统一处理 → 组合；大量对象重复的不可变状态 → 享元。

**先比较更简单方案：** 对象少、无内存证据时不要提前引入共享池；平面数据也不必强建对象树。

### 行为怎样变化

[策略](strategy.md) / [状态](state.md) / [模板方法](template-method.md)

客户端选择算法 → 策略；领域事件驱动阶段转换 → 状态；流程骨架固定、局部步骤扩展 → 模板方法。

**先比较更简单方案：** 少数稳定分支/函数参数往往已足够；三种模式不是消除所有 if 的万能药。

### 请求怎样流转

[命令](command.md) / [责任链](chain-of-responsibility.md)

请求需要保存、排队或撤销 → 命令；请求需经若干处理者择路/短路 → 责任链。

**先比较更简单方案：** 持久队列、重试、幂等不是模式自动提供的能力；直接调用仍是基线方案。

### 对象怎样协作

[观察者](observer.md) / [中介者](mediator.md) / [外观（门面）](facade.md)

一个变化通知多个订阅者 → 观察者；多个同事由中心规则协调 → 中介者；客户端只想更简单入口 → 外观。

**先比较更简单方案：** 通知与业务决策应分清；简单的一对一调用不用事件总线。

### 怎样访问树与集合

[迭代器](iterator.md) / [访问者](visitor.md) / [解释器](interpreter.md) / [组合](composite.md)

只关心遍历 → 迭代器；节点类型稳定且常加操作 → 访问者；为小语法定义求值 → 解释器；树形组织本身 → 组合。

**先比较更简单方案：** 成熟语言/复杂语法优先专用解析器；封闭小 AST 可以用 enum/模式匹配。

### 复制、历史与撤销

[原型](prototype.md) / [备忘录](memento.md) / [命令](command.md)

创建另一个初始状态相似的对象 → 原型；恢复原对象过去状态 → 备忘录；记录做过的操作与补偿 → 命令。

**先比较更简单方案：** 先定义深/浅复制、外部资源及历史大小；复制不是撤销，补偿也未必是逆运算。

### 共享实例还是共享数据

[单例](singleton.md) / [享元](flyweight.md)

特定作用域确需单一实例 → 单例；按键共享多份不同内在状态 → 享元。

**先比较更简单方案：** 优先比较显式依赖注入与不可变配置；全局访问方便不构成使用单例的充分理由。

## 阅读与实施顺序

一次只打开最相关的 1–3 个模式详页；明确输入/输出和失败契约后再写实现。示例的内嵌断言与工程测试建议分开：后者不代表已全部执行。
