# Swift · 设计模式选择指南

[← Skill 入口](../../SKILL.md) · [验证记录](../../docs/VERIFICATION.md)

**代码目标：Swift 6 语言模式。** 目标版本不是所有发行版/平台的兼容性承诺，实测版本见验证记录。

本语言来自用户参考站的语言目录；本项目示例为独立新编。

## 先看本语言的取舍

- 协议/struct 值语义优先；必须有身份和继承需求时再选择 class，any existential 与泛型绑定时机不同。
- Array/String 是值语义，但数组中的 class 实例仍可共享；ARC 闭包引用环需要 weak 或显式生命周期。
- 以 Swift 6 模式编译；同步示例不擅自声明 Sendable，真实 UI/并发流程应明确 @MainActor 或 actor 隔离。

## 创建型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [工厂方法 · Factory Method](factory-method.md) | 框架已经有创建者扩展点，需要让扩展实现决定具体产品。 | 只有一个稳定构造函数，或一个配置到构造函数的映射已经足够。不要为了一个 new 增加整套继承树。 | Swift 无 abstract 类关键字，此继承教学版在基类扩展点显式失败，子类必须覆写。 |
| [抽象工厂 · Abstract Factory](abstract-factory.md) | 需要切换主题、平台、协议家族，且一个家族包含多种必须配套的产品。 | 只有一个产品种类，或者产品之间不需要兼容约束。 | 协议声明产品种类，struct 值产品避免不必要的身份和 ARC 管理。 |
| [生成器（建造者） · Builder](builder.md) | 有多步骤、可选字段、跨字段校验，或需要用相同组装过程产出不同表示。 | 少量必填参数可由清晰构造函数、命名参数或不可变记录解决。 | 类建造器便于链式原地修改，struct Report 和 Array/String 的值语义形成独立快照。 |
| [原型 · Prototype](prototype.md) | 对象配置昂贵、类型运行时确定，或用户从已有模板派生对象。 | 对象含不可复制资源，或直接构造简单值已足够。 | String 和嵌套 Array 使用值语义，写时复制是实现优化而非共享可变值语义。 |
| [单例 · Singleton](singleton.md) | 确有唯一实例约束的进程内只读配置或协调对象，且其边界已被证明。 | 只是为了方便调用；需要按租户、请求、测试隔离，或实际上应该使用依赖注入。 | static let 共享只读配置，final class 的不可变 Sendable 状态通过 Swift 6 检查。 |

## 结构型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [适配器 · Adapter](adapter.md) | 集成遗留代码、第三方 SDK 或不兼容协议，需要做可追踪的边界转换。 | 新旧接口本已一致；或适配层掩盖了无法保证的语义兼容性。 | struct 组合旧 API 并满足新协议；显式 Double 转换保证单位语义。 |
| [桥接 · Bridge](bridge.md) | 产品确实存在两个独立、持续变化的维度，例如消息形式 × 发送渠道。 | 只有一个变化维度，或所谓第二维只是一个固定实现细节。 | 通知层次与 Channel 协议组合形成两个独立轴。 |
| [组合 · Composite](composite.md) | 领域天然是树形的整体—部分结构，叶子与容器存在有意义的共同操作。 | 结构本质是含环的图，或共同接口必须塞入大量叶子不支持的操作。 | 协议 existential 集合统一叶子与组合；值 Bundle 使树成员列表复制明确。 |
| [装饰 · Decorator](decorator.md) | 功能要在运行时按需叠加，包装与被包装对象具有可替换的契约。 | 只是一次简单函数变换，或包装后已经改变了原接口语义。 | 值包装器保留 Text 协议，无需基类。 |
| [外观（门面） · Facade](facade.md) | 存在真实的多组件子系统，客户端只需要少数稳定用例。 | 一个入口不断承接所有业务职责，逐渐形成上帝对象。 | throws 将失败显式放进协调 API，而非用 try? 吞掉错误。 |
| [享元 · Flyweight](flyweight.md) | 内存测量显示重复、可共享的状态占比高，且共享对象可保持不可变。 | 对象数量很少、键空间巨大，或共享可变数据带来的同步成本超过节省。 | class Style 明确演示共享身份，struct Glyph 保存外在值。 |
| [代理 · Proxy](proxy.md) | 需要延迟加载、访问保护、缓存或远程调用边界，且客户端仍面向相同主体契约。 | 仅为隐藏所有网络成本或失败而宣称远程对象和本地对象完全透明。 | 可空引用清晰表达未初始化状态；没有 force unwrap。 |

## 行为型

| 模式 | 适用信号 | 不使用的基线/警报 | 本语言实现提示 |
|---|---|---|---|
| [责任链 · Chain of Responsibility](chain-of-responsibility.md) | 处理顺序可配置，并且停止条件、默认结果与传递语义明确。 | 必须执行的步骤不允许跳过，却使用可能无人处理的隐式链。 | 存储闭包需 @escaping；此同步验证链没有 @Sendable 并发契约。 |
| [命令 · Command](command.md) | 需要排队、历史记录、延迟执行、撤销，或将请求传给通用调用器。 | 调用没有生命周期、历史或排队需求，一个函数已充分表达意图。 | 引用接收者配合私有枚举明确生命周期；throws 报告顺序错误。 |
| [解释器 · Interpreter](interpreter.md) | 文法小且稳定、表达式可以组成语法树，需要可控的领域规则求值。 | 语言复杂或不可信输入需要完整解析、资源治理；此时应使用成熟解析器/执行引擎。 | 协议节点承载 AST，字典查询区分缺失值，加法显式检测溢出。 |
| [迭代器 · Iterator](iterator.md) | 需要统一遍历不同集合、惰性读取，或让多个遍历彼此独立。 | 语言已经提供足够的集合协议，却再包装出不兼容的 next/hasNext 框架。 | Sequence/IteratorProtocol 是惯用入口；游标是可变值，两个 makeIterator 独立。 |
| [中介者 · Mediator](mediator.md) | 多个组件有明确的一组协作规则，需要减少组件间相互引用。 | 只有简单广播，没有集中决策；或者中介者膨胀到管理整个系统。 | Dialog 拥有控件，闭包用 [weak self] 打破 ARC 强引用环；不用 unowned 假定中介者永远存活。 |
| [备忘录 · Memento](memento.md) | 需要撤销、检查点或恢复，且快照大小与敏感信息可控。 | 状态巨大或包含不可恢复的外部副作用；不能把快照当成分布式事务。 | String 值语义保存独立文本；快照强持身份令牌，避免单纯地址复用。 |
| [观察者 · Observer](observer.md) | 一个对象变化需要通知动态集合的订阅者，订阅生命周期可管理。 | 需要持久消息、跨进程投递或恰好一次保证，却只有内存回调列表。 | 复制 Dictionary 值形成当前轮快照，不保证监听顺序。 |
| [状态 · State](state.md) | 同一对象有明确状态图，不同状态的行为或转换规则会继续扩展。 | 只有两个简单状态且分支集中，枚举与清晰条件表达已足够。 | 状态 struct 返回下一态，避免不必要的状态对象引用环。 |
| [策略 · Strategy](strategy.md) | 存在真实、可互换的算法族，需要独立测试或运行时选择。 | 只有一条稳定算法，或者参数本身已能清楚表达差异。 | 闭包是单操作策略的自然表达；存储回调需 @escaping，多任务使用则需重新设计 Sendable 与隔离。 |
| [模板方法 · Template Method](template-method.md) | 流程骨架稳定，已有合理继承/trait 扩展点，部分步骤需要定制。 | 子类需要随意改变流程顺序，或组合函数比继承更清晰。 | final 固定流程，继承步骤因 Swift 无 abstract 使用显式失败占位契约。 |
| [访问者 · Visitor](visitor.md) | 节点类型集合相对稳定，新增操作比新增节点类型更频繁。 | 节点类型经常变化，或简单模式匹配已经更清楚。 | accept 调用类型明确的协议要求完成双分派；新增节点必须扩展所有访问者。 |

## 横向选择：先定位变化轴

### 对象如何产生

[工厂方法](factory-method.md) / [抽象工厂](abstract-factory.md) / [生成器（建造者）](builder.md)

已有创建者扩展点 → 工厂方法；必须配套的一族产品 → 抽象工厂；分步构建且须校验完整性 → 生成器。

**先比较更简单方案：** 只有一个稳定构造过程时，用构造函数、具名参数或简单构造函数映射即可。

### 包装一个对象

[适配器](adapter.md) / [装饰](decorator.md) / [代理](proxy.md) / [外观（门面）](facade.md)

接口不兼容 → 适配器；同契约叠加责任 → 装饰；控制访问/按需创建 → 代理；简化多个子系统 → 外观。

**先比较更简单方案：** 不能只看包装类外形判定；先说明客户端契约是否改变。

### 组织对象结构

[桥接](bridge.md) / [组合](composite.md) / [享元](flyweight.md)

两个独立变化轴 → 桥接；整体与部分统一处理 → 组合；大量对象重复的不可变状态 → 享元。

**先比较更简单方案：** 对象少、无内存证据时不要提前引入共享池；平面数据也不必强建对象树。

### 行为怎样变化

[策略](strategy.md) / [状态](state.md) / [模板方法](template-method.md)

客户端选择算法 → 策略；领域事件驱动阶段转换 → 状态；流程骨架固定、局部步骤扩展 → 模板方法。

**先比较更简单方案：** 少数稳定分支/函数参数往往已足够；三种模式不是消除所有 if 的万能药。

### 请求怎样流转

[命令](command.md) / [责任链](chain-of-responsibility.md)

请求需要保存、排队或撤销 → 命令；请求需经若干处理者择路/短路 → 责任链。

**先比较更简单方案：** 持久队列、重试、幂等不是模式自动提供的能力；直接调用仍是基线方案。

### 对象怎样协作

[观察者](observer.md) / [中介者](mediator.md) / [外观（门面）](facade.md)

一个变化通知多个订阅者 → 观察者；多个同事由中心规则协调 → 中介者；客户端只想更简单入口 → 外观。

**先比较更简单方案：** 通知与业务决策应分清；简单的一对一调用不用事件总线。

### 怎样访问树与集合

[迭代器](iterator.md) / [访问者](visitor.md) / [解释器](interpreter.md) / [组合](composite.md)

只关心遍历 → 迭代器；节点类型稳定且常加操作 → 访问者；为小语法定义求值 → 解释器；树形组织本身 → 组合。

**先比较更简单方案：** 成熟语言/复杂语法优先专用解析器；封闭小 AST 可以用 enum/模式匹配。

### 复制、历史与撤销

[原型](prototype.md) / [备忘录](memento.md) / [命令](command.md)

创建另一个初始状态相似的对象 → 原型；恢复原对象过去状态 → 备忘录；记录做过的操作与补偿 → 命令。

**先比较更简单方案：** 先定义深/浅复制、外部资源及历史大小；复制不是撤销，补偿也未必是逆运算。

### 共享实例还是共享数据

[单例](singleton.md) / [享元](flyweight.md)

特定作用域确需单一实例 → 单例；按键共享多份不同内在状态 → 享元。

**先比较更简单方案：** 优先比较显式依赖注入与不可变配置；全局访问方便不构成使用单例的充分理由。

## 阅读与实施顺序

一次只打开最相关的 1–3 个模式详页；明确输入/输出和失败契约后再写实现。示例的内嵌断言与工程测试建议分开：后者不代表已全部执行。
